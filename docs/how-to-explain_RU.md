# Как читать EXPLAIN

Используйте `EXPLAIN (ANALYZE, BUFFERS)`, чтобы сравнить, что PostgreSQL запланировал, с тем, что реально произошло.

- Seq Scan: PostgreSQL прочитал таблицу напрямую. Это может быть нормально для маленьких или широких сканирований и подозрительно для селективных lookup.
- Nested Loop: полезен при маленьком внешнем входе, но болезнен, когда много раз повторяется поверх больших внутренних сканирований.
- Hash Join: часто хорош для JOIN по равенству, но проверяйте размер build-стороны и оценки строк.
- Bitmap Scan: часто появляется, когда PostgreSQL совмещает селективность индекса с доступом к heap.
- Sort Spill: временные буферы read/write указывают, что сортировка или hash-работа превысили доступную память.
- Buffers: shared hit означает cache, shared read означает чтение с диска/страниц, temp read/write означает рабочие файлы.
- Planning Time и Execution Time: planning - накладные расходы оптимизатора; execution - работа самого запроса.

Всегда сравнивайте корректность результата, прежде чем считать более быстрый запрос лучшим.
