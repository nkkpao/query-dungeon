# Рабочий процесс оптимизации запросов

1. Запустите плохой запрос и сохраните его результат.
2. Снимите `EXPLAIN (ANALYZE, BUFFERS)`.
3. Определите главный симптом: сканирование, JOIN, сортировка, агрегация или повторяющийся подзапрос.
4. Переписывайте SQL только тогда, когда переписывание сохраняет бизнес-ответ.
5. Добавляйте индекс только тогда, когда форма запроса и распределение данных это оправдывают.
6. Сравните результаты плохого варианта и решения.
7. Запустите бенчмарк для обоих вариантов на одном и том же масштабе seed-данных.
8. Объясните компромисс: хранение, стоимость записи, специфичность и сопровождение.
