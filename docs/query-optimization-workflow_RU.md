# Рабочий процесс оптимизации запросов

1. Прочитайте `challenge.md` и зафиксируйте бизнес-ответ, который должен вернуть запрос.
2. Запустите `baseline.sql` через `run-sql`; запишите форму результата и число строк.
3. Снимите `EXPLAIN (ANALYZE, BUFFERS)` через `explain-file`.
4. Назовите главный симптом: scan, join, sort, aggregate, повторный подзапрос,
   ошибка оценки строк или давление на buffers.
5. Скопируйте baseline в `workspace/sql/` и меняйте по одной гипотезе.
6. Ручные индексы кладите в `workspace/indexes/` и запускайте явно.
7. Проверяйте попытку через `validate-file` до того, как верить скорости.
8. Измеряйте через `benchmark-file --baseline --iterations 3` на том же seed.
9. Сравнивайте собственные попытки через `diff-results`.
10. Записывайте компромисс: место, цена записи, специфичность, сопровождение и
    случаи, где идея может не помочь.

Предлагаемые решения нужны для осознанного разбора, а не для обычного цикла
исследования.
